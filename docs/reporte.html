1Resumen

Se construyó una aplicación en Flet que reemplaza por completo el formulario de ejemplo (nombre, casilla de términos, slider, lista de colores, opciones de framework y switch de notificaciones). Cada control ahora actúa sobre un ESP32 programado en MicroPython y simulado en Wokwi, y la app muestra en vivo lo que el ESP32 mide.

El punto de partida fue el código de referencia que conecta el ESP32 al WiFi Wokwi-GUEST y consulta una API con urequests. Ese código se convirtió en un firmware completo: el ESP32 levanta su propio servidor web en el puerto 80 y, además, se conecta a un broker MQTT. Las dos vías usan exactamente el mismo formato JSON.

2Arquitectura y por qué MQTT

El requisito inicial era que el ESP32 fuera el servidor web. El firmware lo cumple: atiende GET /api/estado, POST /api/control y sirve una página propia en /. Sin embargo, el simulador web de Wokwi sólo permite que el ESP32 haga conexiones de salida; para entrar a él desde la computadora hace falta el Private IoT Gateway, que es una función de pago.

Por eso se agregó MQTT. Con MQTT nadie necesita entrar al ESP32: tanto el ESP32 como la app se conectan hacia afuera al mismo broker y ahí intercambian mensajes. Funciona con la cuenta gratuita de Wokwi y sin instalar ningún gateway.

Decisión de diseño. En lugar de elegir una sola vía, el firmware mantiene las dos. MQTT es la que se usa con Wokwi gratis; el servidor HTTP queda disponible para quien tenga el Private Gateway, para una placa ESP32 física en la misma red WiFi, o para probar desde un navegador. En la app se elige con un selector MQTT / HTTP directo.

Sincronización en ambos sentidos

La app no sólo envía: también adopta el estado real del ESP32. Si el LED se cambia desde otro lugar (por ejemplo, desde la página propia del ESP32), el botón de la app se actualiza solo. Para no «regresar» un control que el usuario acaba de mover, durante 2 segundos se ignora lo que diga el ESP32 sobre ese control.

Estados de conexión

El indicador del encabezado muestra en línea, con el tipo de conexión y la latencia, o sin conexión, con un mensaje que explica qué revisar.

5Protocolo de comunicación

El tema base es unah/paradigmas/<CODIGO>. El código (por defecto unah-esp32-4821) debe ser igual en wokwi/main.py y en la app; así varios estudiantes pueden usar el mismo broker público sin mezclarse.

Por HTTP el contenido es el mismo: POST /api/control recibe el JSON de comandos y responde el estado; GET /api/estado?desde=N devuelve el estado con los eventos cuyo id es mayor que N.

  "tiempo_activo": 142,
  "memoria_libre": 80384,
  "mqtt": true,
  "sensores": {
    "temperatura": 40.0, "humedad": 55.0,
    "potenciometro": 20, "pulsaciones": 2 },
  "salidas": {
    "led": false, "nivel": 100,
    "efecto": "termometro", … },
  "servo_grados": 180,
  "anillo": ["#d4002a", … 16 colores],
  "eventos": [{ "id": 17, "t": 120,
    "tipo": "aviso",
    "texto": "Alerta: temperatura alta (40.0 C)" }],
  "ultimo_evento": 17
}

El ESP32 valida cada campo: los números se limitan a su rango, los efectos y frameworks desconocidos se rechazan y un JSON inválido no lo detiene. Cada evento lleva un id creciente; la app recuerda el último que mostró, así no repite eventos y detecta cuándo el ESP32 se reinició (los ids vuelven a empezar).

Paradigmas aplicados

  • Orientado a objetos. Conexion define lo común (cola de cambios, filtro de eventos); ConexionMQTT y ConexionHTTP la heredan y sólo cambian cómo se envía y recibe. La interfaz trabaja con cualquiera de las dos sin saber cuál es (polimorfismo).
  • Orientado a eventos. Cada control de Flet reacciona a su evento (on_change, on_click); en el ESP32, el botón usa una interrupción y MQTT un callback al recibir.
  • Concurrente. El ESP32 usa asyncio para atender HTTP, MQTT, sensores, anillo y pantalla a la vez en un solo núcleo. En la app, Flet ejecuta los eventos en otros hilos, por eso la cola de cambios pendientes se protege con un threading.Lock.

Cambios agrupados

Al arrastrar el slider se generan decenas de eventos por segundo. En vez de mandar uno por uno, la app los acumula en un diccionario de pendientes y el ciclo de sincronización envía sólo el último valor de cada campo. Si el envío falla por red, se reintenta sin pisar cambios más nuevos y sin repetir acciones como la melodía.

8Limitaciones

  • HTTP directo con Wokwi requiere pago. El servidor web del ESP32 funciona, pero en el simulador web sólo se alcanza con el Private IoT Gateway (plan Hobby de Wokwi). Con la cuenta gratuita se usa MQTT.
  • Broker público. Cualquiera que conozca el tema podría leer o enviar mensajes. Para la demo se mitiga usando un código propio. La alternativa es un broker privado.
  • Mosquitto propio con ngrok. Está preparado (tools/mosquitto.conf) y probado en local, pero el túnel TCP de ngrok exige registrar una tarjeta en la cuenta gratuita, y su dirección cambia cada vez que se reinicia ngrok.
  • Recarga de la página en modo web. Flet registra un error interno de WebSocket al recargar la pestaña; no afecta el funcionamiento.

9Cómo ejecutarlo

  1. En wokwi.com, crear un proyecto ESP32 · MicroPython y pegar wokwi/main.py y wokwi/diagram.json. Iniciar la simulación; el serial debe mostrar MQTT listo, tema: unah/paradigmas/unah-esp32-4821.
  2. En la computadora, dentro del proyecto: 
    uv run flet run            # app de escritorio
uv run flet run --web      # o en el navegador
  3. Dejar la conexión en MQTT con broker broker.hivemq.com:1883 y el mismo código que en el firmware. Aceptar los términos y usar los controles.

Sin Wokwi: uv run python tools/esp32_en_pc.py ejecuta el mismo firmware en la computadora; en esa terminal se escribe boton, temp 38 o pot 25 para simular el hardware.

App · polimorfismo en la conexión (src/esp32.py)

class Conexion:
    def pedir(self, **cambios):            # lo llaman los controles de Flet
        with self._lock:
            self._pendientes.update(cambios)
    async def sincronizar(self) -> dict:   # cada subclase decide cómo
        raise NotImplementedError

class ConexionMQTT(Conexion):
    async def sincronizar(self):
        cambios = self._tomar_pendientes()
        if cambios:
            self._mqtt.publish(self.tema + "/control", json.dumps(cambios))
        return self._filtrar_eventos(dict(self._estado))

class ConexionHTTP(Conexion):
    async def sincronizar(self):
        cambios = self._tomar_pendientes()
        respuesta = await self._http.post(f"{self.url}/api/control", json=cambios)
        return self._filtrar_eventos(respuesta.json())
